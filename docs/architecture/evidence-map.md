# 证据映射（模块 / BCT / 主题 ↔ 文献）

## 文档信息

| 项 | 内容 |
|---|---|
| 用途 | 把 PRD 的可配置参数与行为改变路径，逐条挂到可核验文献上；答辩时用于说明“参数不是拍脑袋” |
| 状态 | **已回填（2026-11-08）**：39 条唯一记录、7 条指南；G4/G5 通过 |
| 上游 | `PRD.md` 第 4、5、10 节 |
| 下游 | `data/knowledge/evidence.json` |
| 边界 | 离线资料文档，不参与产品运行时，不接入 `services/agent-orchestrator` |

> 填表规则：`evidence.json` 里的 `applies_to` 与 `topics` 决定本表回填位置。一个参数可以对应多条文献，
> 但每条文献至少要有一个主题；没有直接文献支撑的参数必须显式标“间接”或“产品规则”，不许留空装成已支撑。

## 4. 与产品边界的关系

- 本表只解释“为什么这么设”，不替代医疗声明。PRD 第 10 节固定措辞与 `safety-check` 中间件不因本表改变。
- `safety-redflag` 主题的文献只能用于**识别与转诊边界**，不得被引用为“产品可做诊断”的依据。
- 任何一条文献都不得让系统越过 `safety-check` 中间件，也不得让端侧获得状态迁移能力。
- 表中“间接 / 产品规则”的条目，答辩时应主动说明边界，不能包装成“文献直接证明 45 分钟或 5/10 次”。

- 维护方式：改参数或补文献时，先更新 `evidence.json` 与本表，再跑上述两条命令。

## 6. 文献使用建议

- 答辩引用优先用 `guideline` 与 `systematic-review`；RCT 用于说明具体干预剂量。
- 反例与阴性结果（如 Cochrane 工作场所干预、蓝领人群反向关联）应主动说明，避免“只挑有利证据”。
- `safety-redflag` 的 8 条红线是产品汇总，不是诊断标准；对外表述必须保留“就医提示”边界。
