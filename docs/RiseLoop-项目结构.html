Rise Loop
久坐行为干预系统

一个状态机驱动的久坐行为干预系统：感知久坐 → 按当前状态推送最短有效动作 → 采集反馈 → 自动迁移状态。 本页以文档形式可视化其完整代码结构、分层架构、数据流转与工程现状，作为项目认知的单一入口。

边界声明（一以贯之）：本产品是健康行为指导工具，不做医疗诊断与治疗。任何运动推荐前都经过 safety-check 中间件；出现放射痛、麻木加重、下肢无力等红旗信号立即短路回 S0 并引导就医。 本期不做浏览器端 Demo，不做实时可穿戴接入（仅预留事件表），演示以 Tauri 桌面端 + 录屏兜底。
01

全景架构

系统在部署上分为「端侧 / 云侧」两块，在代码职责上遵循三层分离： 编排层（CodeArts 双 Agent）→ 能力层（4 个 Skill）→ 工具层（3 个 MCP 工具），事实数据走 RDS、实时状态走 Redis。 需要强调的是：状态迁移的确定性主链路不经过大模型，由 intervention-engine 纯函数直接结算；Agent 只承担编排与知识问答。

04

核心流程

三条闭环各自独立：云端主闭环、本地离线闭环、姿态感知链路。每步标注了负责代码，便于定位。

4.1 云端主闭环（评估 → 触发 → 执行 → 反馈 → 迁移）

1

认证

注册/登录签发 JWT；客户端经 IPC 把令牌写入 OS Keychain，不落 localStorage、不向前端暴露原始凭据。

POST /auth/register · /auth/logincore/security.py · commands.rs
2

首次评估

提交不适部位、久坐时长、可用时间、疼痛评分；安全中间件先扫红旗，再输出初始状态（S0/S1）、风险等级与两周计划。

POST /assessmentservices/assessment.py → RDS assessments
3

久坐计时

Rust 后台每秒 tick，默认阈值 45 分钟、可配 30–60；窗口最小化到托盘不中断。

src-tauri/src/timer.rs · lib.rs事件 riseloop://tick
4

心跳触发

客户端每 60 秒上报心跳；云端判阈值 + 10 分钟冷却（Redis），按「同状态优先 → 部位重合 → 时长升序」匹配最多 3 个动作。

POST /sitting/heartbeatservices/heartbeat.py · Redis session
5

推送展示

自制透明通知窗优先，不可用时回退系统通知；点击唤回主窗口，进入干预遮罩与倒计时。

src-tauri/src/notice.rssrc/notice/ · ActivityPanel.vue
6

提交反馈

完成/部分/跳过 + 感受 + 疼痛评分 + 障碍归因（太忙/太难/没地方/忘了）；再次过安全短路。

POST /intervention/feedbackcomponents/InterventionCard.vue
7

状态迁移

纯函数 decide() 结算下一状态；非 HOLD 的迁移写入 state_transitions，执行记录写 intervention_logs，同步 Redis session。

packages/intervention-engine/machine.pyservices/feedback.py

4.2 本地离线闭环（无网络）

1

显式进入

登录页底部「进入本地模式」，切到 local-engine，不发任何网络请求，常驻「本地模式」徽标；不会在云端故障时自动切换。

state/session.js enterDemo()
2

本地评估与动作

同一套初始状态判定与动作匹配，动作库复用 data/actions/actions.json 只读导入。

packages/local-engine/src/index.js · actions.js
3

本地迁移与复盘

JS 版 decide() 镜像四分支迁移；周复盘按同口径统计完成率、疼痛趋势、阻碍分布。

machine.js · safety.js
4

本机持久化

全部数据写 localStorage（键 riseloop.local.v1）；智能问答返回 501「本地不可用」。

localStorage riseloop.local.v1

4.3 姿态感知链路（11.10 路线决策）

1

端侧关键点提取

MediaPipe Pose Landmarker（JS/WASM）在 Tauri WebView 内提取 33 个归一化关键点，原始画面只在本地，不上传。

public/mediapipe/ · state/postureMonitor.js
2

云端推理

POST 关键点 → 安全中间件 → posture_infer.py → ModelArts 适配层（mock | huawei，2.5s 超时），返回姿态分类、置信度与来源。

POST /posture/infercloud/modelarts.py
3

风险融合（BRLI）

久坐负荷 + 姿态异常持续性 + 恢复 + 症状四分量加权得到可解释风险指数与等级，附证据引用。

packages/intervention-engine/risk.pyPOST /posture/risk
4

摘要落库与降级

只落「类别、置信度、BRLI、时长、来源」到 RDS（60s 写节流），Redis 缓存 600s；ModelArts 不可用返回 503 显式降级，不伪造结果。

posture_summaries · posture:latest:{user}
姿态链路的关键点提取、调用链、超时与降级均已落地；但 ModelArts 尚无真实 endpoint，目前走 mock + 端侧回退，真人关键点精度也尚未在演示机验证。
05

四状态机

核心业务逻辑，纯函数实现，表驱动单测覆盖。迁移五类：upgrade / rollback / degrade / short_circuit，以及内部 hold。

S0
急性缓解
≤2 分钟 · gentle

进入：明显酸痛/紧绷或主动报告不适。
退出：完成 2–3 次、评分 ≤3、次日无加重。

S1
激活
2–3 分钟 · normal

进入：S0 完成或无急性症状。
退出：连续完成 ≥5 次。

S2
强化
5–8 分钟 · 一轮 2–3 条

进入：S1 稳定。
退出：连续完成 ≥10 次。

S3
维持
2–3 分钟 · normal

进入：S2 完成或稳定期。
退出：长期维持，异常回退。

迁移五分支（machine.py 的实际语义）
类型触发条件处理代码要点
upgrade满足各状态退出条件升一级，时长按新状态区间S0 需 s0_completed≥2 且 pain≤3 且 !next_day_worse；S1 连续 ≥5；S2 连续 ≥10
rollback连续 2 次症状加重回退一级（S3→S2→S1→S0），S0 停留feeling==WORSE 或 next_day_worse → worse_streak+1；仅 1 次则 HOLD 观察
degrade连续 3 次跳过 / 没感觉且无加重不降状态，同状态换更低强度、更短动作completion==SKIPPED → skipped_streak+1；gentle 时长（S1 2–3 / S2 3–5）
short_circuit任一高危红旗立即回 S0 + 就医提示，停止推荐feedback.red_flags 非空即短路；中间件已先行 403
hold部分完成 / 未达阈值 / 仅 1 次加重保持当前状态partial 完成不计入连续完成，清零连续计数

8 类安全红旗（命中即短路）

放射痛radiating_pain 麻木加重numbness_worse 眩晕dizziness 下肢无力leg_weakness 踩棉花感cotton_wool_gait 大小便异常bowel_bladder 会阴麻木perineal_numbness 外伤后剧痛post_trauma_severe_pain
阈值依据：久坐阈值默认 45 分钟（可配 30–60），同一用户 10 分钟内不重复推送；单次干预 2–10 分钟均落在证据窗口内。每次迁移写 from_state / to_state / reason / transition_type / timestamp。
06

数据与接口

双存储职责严格分离：RDS 存事实、Redis 存实时状态，不得混用。下表为迁移文件与 ORM 模型的对照。

RDS 事实表（PostgreSQL）

  • users账号 / 密码哈希 / 软删除
  • assessments首次评估 / 初始状态 / 计划
  • state_transitions迁移历史（四分支）
  • intervention_logs执行记录 / 反馈 / 障碍归因
  • actions动作库（按状态）
  • sitting_events久坐事件（可穿戴预留）
  • qa_logs问答日志与引用
  • safety_events安全短路事件
  • posture_summaries姿态摘要（仅 ORM，见下）
  • session:{user}:state当前状态 / 计数器（TTL 86400s）
  • sitting:{user}:timer久坐计时（TTL 86400s）
  • pending_intervention:{user}待响应干预
  • safety:{user}:ttl安全短缓存
  • posture:latest:{user}最近姿态摘要（TTL 600s）
Redis 只放实时状态类 Key，不做普通缓存滥用；健康档案不落 Redis。
一致性缺口：ORM 模型 db/models.py 定义了 PostureSummary（posture_summaries），但 infra/migrations/0001_init.sql 尚未包含该表的建表语句 —— 真实接线 RDS 前需要补迁移，否则姿态摘要无法落库。

约束红线

来自 AGENTS.MD 的架构红线，违反即重做。这是理解「为什么代码这样组织」的底层依据。

  1. 状态迁移收口：云端链路收口到 intervention-engine，本地模式收口到 local-engine，两端规则一致；Tauri 端禁止迁移逻辑。
  2. 本期禁止新增浏览器端：不得私下实现 Web Demo 或第二套业务逻辑。
  3. Skill 禁止直连数据库、互相隐式调用：所有数据访问必须经 MCP 工具。
  4. cloud-api 禁止：绕过 safety-check 输出运动推荐；把智能体密钥下发客户端。
  5. MCP 工具固定 3 个：read_realtime_state / get_actions_by_state / write_intervention_result，不得私扩。
  6. 双存储职责：RDS 存事实、Redis 存实时状态，不混用。
  7. 华为云绑定：核心 AI 走 CodeArts 智能体与华为 AI 技术，禁止纯第三方大模型套壳。
  8. 本地模式边界：本地模式不发网络请求、不自动切换；正式评审不得以本地模式替代云端公网链路验证。
  9. 安全与凭据：JWT 不暴露给前端、不落 localStorage（走 Keychain + IPC）；健康检查不返回 DSN/密码/AK-SK/原始健康数据。
